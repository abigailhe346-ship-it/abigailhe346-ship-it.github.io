01

缘起 Pourquoi

The Problem

学法语的第三年，我发现了矛盾的现状：最好的语料在 YouTube 上——哲学对谈、心理学科普、日常 vlog——但「看视频」和「学习」之间隔着一整套手工劳动：找视频、抄句子、查单词、做卡片。一小时的内容，消化要花三小时。

于是我写了 FrenchTube：把这套手工劳动编译成一条流水线。分类与口味写进一个 config.yaml，cron 每天早上 8:17 触发抓取；无字幕的视频走 faster-whisper 本地转写；查词结果终身缓存，同一个词永远不付第二次 API 费用。

「不是又一个刷词 App，而是一座私人电视台——只播法语，且每一帧都可以点开查词。」
02

流水线 Pipeline

Hover each stage · 悬停查看每一环
ÉTAPE 1

抓取

yt-dlp 按 config.yaml 的分类关键词搜索，watchlist 优先；每类补齐到目标数，失败自动降级。
ÉTAPE 2

转写

有字幕直接拉取；无字幕抽音频走 faster-whisper（small, fr）本地转写，不花一分钱 API。
ÉTAPE 3

分析

LLM 选出 60–120 秒高价值片段，批量翻译逐句、提取核心词汇与句式语法，每视频至多 2 次调用。
ÉTAPE 4

切片

ffmpeg 切出精学 mp4；逐句 ▶ 循环精听，落在片段内播本地切片，否则 YouTube IFrame seek。
ÉTAPE 5

练习

词汇进 SM-2 队列，四档评分调度复习；词库支持静音、掌握度筛选与手动添加。

06

技术栈 Stack

Everything runs on one laptop
Backend
Flask + SQLite
单文件 app.py 驱动全部 API；八张表落一颗 app.db，后台补齐任务写 nohup 日志。
Acquisition
yt-dlp + Whisper
支持 yt-dlp 全部站点；无字幕视频本地转写，失败优雅降级为 no-transcript 预览。
Intelligence
LLM 预算制
翻译批量合并、查词缓存优先——词典命中时只在缺中文时补一次调用，同一词终身一次。
Dictionary
kaikki.org → 82k
547MB 法语 Wiktionary 提取，按 50k 频率表 ∩ 词源信息过滤入库，含 IPA 与派生词。
Scheduling
SM-2 四档
重来 / 困难 / 良好 / 简单驱动 EF 系数与间隔，reps≥3 记为已掌握。
Frontend
Vanilla JS
无框架单页：逐句对照、精听循环、练习队列与词库管理，全部手写。
